# Nuomi 漫剧技能一致性重构设计

## 背景

`nuomi-drama-skills` 同时包含创作指导、确定性编译、独立生成和平台导出能力。初步只读审计确认：44 个 Python 文件均可解析，提示词检查与视频分组 smoke test 通过，示例手稿可成功导出；但完整 pytest 尚未运行，因为当前环境缺少 pytest。

当前主要风险是技能说明与代码现状漂移，包括字面量 `\n`、错误参考路径、章节乱序、契约版本不一致、不存在的模块，以及“只在平台生成”和“支持独立生成”之间的职责冲突。优化需要同时覆盖技能说明、Python 管线、依赖、测试和文档一致性，并保持现有手稿及平台项目格式兼容。

## 目标

1. 确认现有创作、编译、生成和导出链路的真实行为。
2. 复现并修复代码、文档、依赖或契约中的缺陷。
3. 让 `SKILL.md` 成为清晰、准确、按需加载的阶段路由。
4. 借鉴同目录 `short-drama` 的阶段入口、状态恢复和参考资料路由，但不照搬其目录或长篇剧本假设。
5. 建立可复现的本地环境与离线测试闭环。
6. 保持旧手稿、CLI 和平台 JSON 的兼容性，除非测试证明原行为错误。

## 非目标

- 不调用真实图片、视频、配音或其他付费 Provider API。
- 不重写平台项目契约或创作方法论。
- 不进行与本次一致性重构无关的代码整理。
- 不为匹配过时文档而创建没有真实用例的空模块。

## 整体边界

技能继续保留三层能力：

1. **创作层**：立意、三轴、大纲、五表圣经、分卷节拍、逐集剧本和分镜。
2. **编译层**：以 `manuscript/*.md` 为唯一创作事实源，经 `export.py` 输出平台项目 JSON。
3. **生成层**：由 `generate.py` 提供图片、视频、配音、音色和状态查询；仅当用户明确要求生成时才能调用外部 Provider。

`SKILL.md` 只保留触发条件、阶段路由、关键铁律、资源导航和常用命令。格式规范、平台契约、题材方法论和生成细节继续放在参考文件中，按阶段加载。

## 技能工作流

### 启动与恢复

每次启动先检查当前工作目录：

- 已存在 `manuscript/` 或状态文件时，读取已有产物，报告当前阶段、完成集数、缺失项和建议的下一步。
- 新项目进入策划流程：立意与三轴 → 大纲 → 五表圣经 → 分卷节拍表。
- 骨架锁定后进入批量产集，按用户指定范围生成逐集剧本和分镜。
- 审核、导出、状态诊断和恢复可单独执行，不要求从头重走流程。

### 交互规则

- 上游高杠杆阶段一次处理一个决策，确认后再写手稿。
- 用户回复简短时给出单一推荐和理由，减少不必要的开放式追问。
- 批量产集前读取对应卷节拍、相关角色与场景、伏笔窗口和前集摘要。
- 命令式入口是快捷方式，自然语言仍是主要触发方式。
- 状态文件仅保存进度与索引，不能替代 `manuscript/*.md`。
- 普通审计、导出和测试不得消耗 Provider 配额。

### 门控

- 导出前运行适用于手稿和分镜的 G1–G6。
- 独立生成前补充运行 G7–G8。
- 软质量问题以 warning 返回并允许用户决定是否继续。
- 契约、交叉引用、生成前置条件或 Provider 配置错误为 hard block。

## 代码审计边界

按真实数据流审计：

- 解析与校验：`manuscript_parse.py`、`validators.py`、`gates.py`。
- 编译与合并：`export.py`、`emit.py`、`contract.py`。
- 状态与扩展：`writing_state.py`、`hooks.py`。
- 生成：`generate.py`、`stages/`、`providers/`、`imaging/`。
- 导出扩展：`exporters/jianying.py`。

只有在真实使用场景和测试需要时才补齐命令路由。所有代码修复遵循“失败测试 → 最小修复 → 回归验证”。

## 依赖与本地环境

在仓库根目录创建 `.venv`。补充可复现的依赖声明，区分运行依赖和测试依赖；覆盖 HTTP 客户端、Pillow、NumPy、YAML、Flask 和 pytest 等实际导入项。`.venv` 必须被 git 忽略。

若现有环境无法联网安装依赖，应明确报告阻塞，并继续完成不依赖缺失包的静态和 smoke 验证；不得通过跳过失败测试来宣称完成。

## 错误处理

- **手稿错误**：指出文件、集号、镜号、字段和具体修复建议。
- **质量提醒**：返回结构化 warning，不阻止编译。
- **契约或前置条件错误**：hard block，禁止写入脏结果或调用 Provider。
- **Provider 单项失败**：写入结构化失败记录，继续处理其他独立任务，并支持精确重试。
- **缺依赖、凭据或 workflow ID**：在网络请求前失败。
- **编译失败**：保持输出原子性，不破坏既有项目。
- **重复编译**：保持幂等，并保留平台已经生成的资产和状态。

## 测试策略

### 基线与修复循环

1. 创建 `.venv` 并安装声明的依赖。
2. 运行现有 pytest，保存真实基线结果。
3. 对每个确认的 bug 先新增失败测试，再实施最小修复。
4. 每次修复后运行针对性测试，最后运行完整回归。

### 测试矩阵

- **文档一致性**：所有本地引用存在；`SKILL.md` 无字面量 `\n`；章节顺序正确；契约版本与 `contract.py` 一致；示例命令对应真实模块和参数。
- **解析与编译**：示例手稿成功导出；非法手稿不落盘；重复导出幂等；平台已有资产和 ready 状态得到保留。
- **门控**：软提醒与硬阻断语义准确，错误定位完整。
- **状态恢复**：能从已有手稿和状态恢复，且状态文件不覆盖手稿事实。
- **CLI**：参数解析、帮助文本、dry-run 和错误退出码一致。
- **生成内部逻辑**：视频分组、提示词规则、目标范围、重试与状态统计。
- **导出扩展**：剪映导出入口及产物结构。
- **Provider**：仅用配置校验、mock 响应和 dry-run，不访问真实服务。

所有文件型测试使用临时目录，避免污染示例和用户项目。

### 最终验证

- 完整 pytest。
- 所有 Python 文件语法检查。
- 技能结构和 frontmatter 校验。
- 示例手稿端到端导出。
- 主要 CLI smoke test。
- 独立子智能体盲测：模拟真实用户请求，验证阶段选择、参考资料加载、状态恢复，以及不会误调用生成 API。

## 验收标准

- 全部声明的测试通过，并提供命令与结果证据。
- `SKILL.md`、README、参考资料和真实代码一致。
- 旧示例与兼容手稿仍可成功导出。
- 不发生真实 Provider 或付费 API 请求。
- 没有已知 hard-block 缺陷或未说明的测试失败。
- git diff 仅包含本次任务相关改动。

## 风险与控制

- **文档驱动误改代码**：以真实实现、契约和回归测试共同判定，不能仅凭文档修代码。
- **兼容性回归**：先固定现有合法输入和输出，再修改实现。
- **依赖安装失败**：明确区分环境问题与代码问题，不弱化验收标准。
- **外部服务副作用**：测试统一 mock/dry-run，并在调用前校验禁止真实网络请求。
- **范围膨胀**：只修复审计确认的问题及支撑一致性所必需的结构。
