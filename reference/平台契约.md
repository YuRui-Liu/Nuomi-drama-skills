# 平台契约（离线事实源）

**FROZEN @ CONTRACT 2026-06-20**（冻结自 nuomi-drama-agent-lab 2026-06-20 源码核查；
版本号见 `contract.py` 的 `CONTRACT_VERSION`）。

本文件是 `export.py` 编译目标的离线权威说明：不装软件、不看源码的人，照此即可理解
产物文件夹为何"丢进去就能用"。`export.py` 内置的冻结校验器(`validators.py`)即镜像
本契约。

---

## 1. 导入模型

- **导入 = 把整个项目文件夹丢进平台的 projects root**。
- 一个目录被识别为项目，**当且仅当**它含 `harness_state.json`（`app.py:1628-1647`）。
  最小合法项目 = `harness_state.json` + `series.json`。
- 各 loader（`SeriesContext.load` / `GenContext.load` / `StoryBible.load` /
  `ArcPlan.load`）对**缺文件惰性建默认**、对**未知字段过滤丢弃**——所以手搓的文件夹
  "丢进去就能用"，平台不会因为多了或少了某个字段而崩。
- **例外**：`story_bible.json` 与 `arcs.json` 走 `cls(**data)` 加载，**不过滤未知键**——
  这两个文件**只能含已知顶层键**，否则构造报错。故 `emit_arcs` / `emit_story_bible`
  绝不写计划外的顶层键。

## 2. 出图前置（为何这套产物能让平台从中段起跑）

- 出图 / 出视频 / 后期都读 `E{n}/gen_context.json` 的 `script` + `storyboard`，
  外加 `series.triplet` 与 `assets/registry.json` 的 anchors。
- 三者就绪即可让平台从 `imagegen` 起跑，**跳过所有上游 LLM 阶段**
  （`pipeline/run.py:337-338`）。这正是本 skill 的价值：人在 Claude 里把上游
  （立意→分镜表）写完，平台只跑下游（出图→视频→后期）。
- 阶段前置：**非 E0 集的 imagegen / video / transition 需 `gen_context.storyboard`**；
  audio / dub 需 `gen_context.audio`（audio 是平台运行时产物，manuscript 不写）。

## 3. 磁盘布局（导入后的项目文件夹）

```
<项目>/
  harness_state.json        # 项目标记(presence = 合法项目);{"passed":[], ...}
  series.json               # 系列级:三轴/大纲/idea/mode/集数
  arcs.json                 # 分卷节拍表(cls(**data),仅已知键)
  story_bible.json          # 规划层四表 + 运行时 episode_digests
  assets/
    registry.json           # 角色/场景/道具资源条目(文字规格 + 出图状态)
  E1/  E2/ ... EN/          # 每集一目录,全 N 集都建
    gen_context.json        # 本集 script + storyboard + 资产/音频(平台产物)
```

## 4. 各 JSON 顶层键

来源 / 并入保留规则见 spec §6。`export.py` 对每个目标文件做"读已有→只改创作键→
保留其余"（在无平台代码下复刻平台 `.mutate()` 语义）。

### `series.json`
- 创作键（export 写）：`project_dir`、`mode`、`episode_count`、`triplet`、`idea`、`outline`。
- 来源：立意 json 块（triplet）+ 大纲 json 块（outline）+ 立意正文（idea）+ mode/集数。
- 并入保留：平台后加的任何未知键。

### `arcs.json`
- 顶层键（仅这些）：`project_dir`、`arcs`。
- 来源：`02_分卷节拍表.md` 的 json 块。
- 注意：`cls(**data)` 加载，**不得含其它顶层键**。

### `story_bible.json`
- 创作键（export 写）：`project_dir`、`characters`、`foreshadows`、`threads`、`canon`。
- 来源：`bible/*.md` 的四张规划表。
- 并入保留：**`episode_digests`**——平台 `bible_writer` 跑流水线时累积的运行时产物，
  export **绝不写它**（新文件给空 `{}`，已有则原样保留）。

### `assets/registry.json`
- 形态：`{"<type>/<id>": entry}`，type ∈ `character / scene / prop`，
  character 的 id 用**短名**（normalize 后；括号描述进 `entry.meta.aliases`）。
- 条目字段：`type / id / name / status / source / anchor_path / meta / overrides`。
- 来源：角色/场景/道具文字规格（`外貌`/`appearance`/`描述`/`aliases`）。
- 并入保留：既有条目**刷新 meta 文字**（appearance / aliases / description），
  但**不降级 status、不丢 anchor_path / overrides**；仅**新条目**设 `status=pending`。
- 图一律平台生：manuscript 只写文字规格。

### `E{n}/gen_context.json`
- 创作键（export 写）：`project_dir`、`mode`、`episode_id`（`E{n}`）、`triplet`、
  `script`、`storyboard`。
- 来源：`episodes/E{n}.md` 的 `## 剧本`（script 散文）+ `## 分镜表` json 块（storyboard）。
- **全集可见**：按大纲 N 为 **1..N 每集都建**——写了的灌满，没写的留 `script=null` +
  空 storyboard（骨架集），导入后 E1..EN 全部列出，无静默缺口。
- 默认键（新文件）：`target_aspect="9:16"`、`idea=null`、`anchors={}`、
  `style_anchor=null`、`shots_assets={}`、`audio=null`。
- 并入保留：**`shots_assets` / `anchors` / `style_anchor` / `audio`**——平台出图/配音产物。

### `harness_state.json`
- 来源：缺则建 `{"passed":[]}`。
- 并入保留：**已有则不覆盖**（保平台跑过的进度：`passed` / `stall_counts` 等）。

---

## 5. 五表边界

manuscript 只写**规划层**四表：`characters` / `foreshadows` / `threads` / `canon`。
`episode_digests` 是平台跑流水线时 `bible_writer` 累积的**运行时产物**，export 绝不写它。

## 6. 错误处理（全部"显错不静默"）

- 校验不过 → 报错指向出错的 manuscript 文件/段，**绝不声称成功**，**不写出任何平台文件**。
- 大纲说 N 集但 `episodes/E{k}.md` 缺 → 仍建骨架 E{k}（可见、`script=null`），
  并在报告里列出哪些是骨架集（无静默缺口）。
- 大纲 N vs 平台已有 M 个集目录不符 → **警告不删**多出的（并入安全）。
- 节拍表引用未知 thread / 伏笔 id → `validate_beats` 拦，带位置报错。
- json 围栏块格式坏 / 分镜缺必填字段 → 带文件名的解析 / schema 错。
